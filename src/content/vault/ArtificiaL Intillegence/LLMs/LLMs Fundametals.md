LLMs (Large Language Models) are the most popular type of AI model used for natural language processing tasks.

## How LLMs Work?

LLMs work by using deep learning techniques and transformer architectures to process and generate human-like text.

## Tokenization

Tokenization is the process of breaking text into smaller units called **tokens**, which are the basic inputs used by Large Language Models (LLMs).

### What is a Token?

A token can be:

- A complete word (`apple`)
- Part of a word (`ap` + `ple`)
- A punctuation mark (`.` or `,`)

LLMs do not directly understand words. Instead, they process text as numerical representations of tokens.

### How It Works

```text
Text
   ↓
Tokenizer
   ↓
Tokens
   ↓
Token IDs (Numbers)
   ↓
LLM Processing
```

### Example

```text
Sentence:
"ChatGPT is amazing!"

Tokens:
["Chat", "G", "PT", " is", " amazing", "!"]

Token IDs:
[1012, 4321, 9876, 523, 7812, 999]
```

### Why Tokenization Matters

#### Efficiency
- Reduces the complexity of processing language.
- Allows models to work with a fixed vocabulary.

#### Robustness
- Rare or unseen words can be split into known subwords.
- Helps the model handle new words and spelling variations.

#### Cost
- Most LLM pricing is based on token count.
- More tokens = higher inference cost.

### Common Tokenizers

- **Byte Pair Encoding (BPE)** → Used in GPT models
- **SentencePiece** → Used in many Google models

### Rule of Thumb

```text
1 Token ≈ 4 Characters ≈ 0.75 Words (English)
```

# Context Window

## What is a Context Window?

A **context window** is the maximum number of tokens an LLM can process at one time.

Think of it as the model's **short-term memory**.

```text
Input Tokens + Previous Conversation + Retrieved Context
                            │
                            ▼
                    Context Window
                            │
                            ▼
                      Generated Output
```

Once the limit is reached, older tokens are removed from the window.

This is known as a **sliding window** mechanism.

---

## Typical Context Sizes

| Model | Context Window |
|---------|---------|
| GPT-3.5 | ~4K Tokens |
| GPT-4 Turbo | ~128K Tokens |
| Claude 3.5 Sonnet | ~200K Tokens |

---

## Why Context Windows Matter

### Chatbots

Long conversations may eventually forget earlier details.

```text
User: My name is Roshan.
...
500 messages later
...
Model may no longer remember the name.
```

### Large Documents

A huge PDF might exceed the context window.

Solution:

- Split document into chunks
- Retrieve only relevant sections
- Feed those sections to the model

This is the foundation of **RAG (Retrieval-Augmented Generation)**.

### Cost

Larger context windows require:

- More memory
- More computation
- Higher inference cost

---

## How Modern Systems Solve Context Limits

### Retrieval-Augmented Generation (RAG)

Instead of sending an entire document:

```text
Question
    ↓
Retriever
    ↓
Relevant Chunks
    ↓
LLM
    ↓
Answer
```

Benefits:

- Lower cost
- Better accuracy
- Handles large knowledge bases

---

### Long-Context Transformers

New transformer architectures are optimized to process hundreds of thousands or even millions of tokens efficiently.

Goal:

```text
More Memory
+
Lower Computation
=
Better Long-Context Performance
```

# Token-Based Pricing

## Why LLM Usage Costs Money

Most commercial LLM APIs charge per token.

Pricing is based on:

```text
Input Tokens
+
Output Tokens
=
Total Billable Tokens
```

---

## Types of Tokens

### Input Tokens

Everything you send to the model.

Examples:

- Instructions
- Documents
- Previous conversation history
- User prompts

### Output Tokens

Everything generated by the model.

Examples:

- Answers
- Summaries
- Code
- Explanations

---

## Example

```text
Prompt:
500 Tokens

Response:
700 Tokens

Total:
1200 Tokens
```

Cost is calculated on those 1200 tokens.

---

## Why Pricing Matters

### Optimize Prompts

Shorter prompts reduce cost.

### Control Output Length

Prevent unnecessarily long responses.

### Budget Forecasting

Production systems often include token counters.

```text
Estimated Tokens
       ↓
Estimated Cost
       ↓
Request Approval
```

# Temperature

## What is Temperature?

Temperature controls randomness during token selection.

It determines how predictable or creative the output will be.

---

## Low Temperature (0.0 - 0.2)

Characteristics:

- Deterministic
- More consistent
- Less creative

Best For:

- Programming
- Math
- Legal documents
- Factual answers

Example:

```text
Prompt:
Suggest a coffee shop slogan.

Output:
"Fresh Coffee Every Day."
```

---

## Medium Temperature (~0.5)

Characteristics:

- Balanced creativity
- Good coherence
- Moderate variation

Best For:

- General assistants
- Educational content
- Business writing

---

## High Temperature (0.8 - 1.0+)

Characteristics:

- More creativity
- More exploration
- Higher hallucination risk

Best For:

- Storytelling
- Brainstorming
- Marketing ideas

Example:

```text
"Awaken Your Senses, One Cup at a Time."
```

---

## Quick Rule

```text
Lower Temperature
    =
More Accurate

Higher Temperature
    =
More Creative
```

---

# Top-p (Nucleus Sampling)

## What is Top-p?

Top-p limits token selection to the most likely words whose cumulative probability reaches a threshold **p**.

Instead of considering all words:

```text
All Words
    ↓
Top-p Filter
    ↓
Most Probable Subset
    ↓
Pick Next Token
```

---

## Example

### Top-p = 0.3

Only very likely words are considered.

Result:

```text
Focused
Consistent
Predictable
```

---

### Top-p = 0.95

Many candidate words enter the pool.

Result:

```text
More Diversity
More Creativity
More Variation
```

---

## Temperature vs Top-p

### Temperature

Changes probability distribution.

```text
How random?
```

### Top-p

Controls candidate selection pool.

```text
Which words are eligible?
```

---

## Best Practice

Often:

```text
Temperature = Moderate

Top-p = High
```

This provides balance between:

- Accuracy
- Diversity
- Coherence

# Frequency Penalty

## What is Frequency Penalty?

Frequency penalty discourages repeated words and phrases.

The more a token appears, the more its probability is reduced.

---

## Example

Without Penalty:

```text
very very very very good
```

With Penalty:

```text
excellent
great
impressive
```

---

## Typical Values

### 0

No penalty.

```text
More repetition possible
```

### Higher Values

```text
Less repetition
More varied wording
```

---

## Best Use Cases

- Long articles
- Customer support bots
- Long conversations
- Content generation

---

# Presence Penalty

## What is Presence Penalty?

Presence penalty encourages introducing new topics and ideas.

Unlike frequency penalty:

- Frequency Penalty → reduces repeated words
- Presence Penalty → introduces new concepts

---

## Example

Prompt:

```text
Explain AI.
```

Low Presence Penalty:

```text
Keeps expanding the same AI concepts.
```

High Presence Penalty:

```text
AI
Machine Learning
Deep Learning
RAG
Agents
Robotics
```

The response explores broader topics.

---

## Typical Behavior

### Low Value

- Focused
- Consistent
- Less exploratory

### High Value

- Creative
- Diverse
- Introduces new ideas

# Stopping Criteria

## Why Do Models Need Stopping Rules?

LLMs always predict the next token.

Without restrictions, generation could continue indefinitely.

---

## Common Stopping Methods

### Max Token Limit

```text
Stop after N tokens.
```

---

### End-of-Sequence Token

Example:

```text
<|end|>
```

When seen, generation stops.

---

### Custom Stop Strings

Examples:

```text
###
END
STOP
```

Used heavily in applications and agents.

---

## Benefits

- Predictable outputs
- Reduced cost
- Better formatting
- Faster responses

---

# Max Length

## What is Max Length?

Max length is the maximum number of output tokens the model can generate.

Think of it as the model's response budget.

---

## Common Ranges

### Short Responses

```text
50–200 Tokens
```

Examples:

- Tweets
- Quick answers
- Headlines

---

### Medium Responses

```text
500–1000 Tokens
```

Examples:

- Blog sections
- Technical explanations
- Documentation

---

### Long Responses

```text
2000+ Tokens
```

Examples:

- Research reports
- Detailed tutorials
- Long-form analysis

---

## Trade-Off

```text
Too Short
    ↓
Incomplete Answer

Too Long
    ↓
Higher Cost
    ↓
More Drifting
```

Goal:

```text
Clarity
+
Relevance
+
Reasonable Cost
```

# Key Takeaways

### Context Window

> Determines how much information the model can see and remember at once.

### Token Pricing

> Every input and output token contributes to cost.

### Temperature

> Controls creativity versus accuracy.

### Top-p

> Selects how broad the candidate token pool is.

### Frequency Penalty

> Reduces repeated words and phrases.

### Presence Penalty

> Encourages new ideas and concepts.

### Stopping Criteria

> Defines when generation should stop.

### Max Length

> Limits response size and controls cost.

---

# The Core Trade-Offs of LLMs

```text
More Context      ↔ Higher Cost
More Creativity   ↔ Lower Reliability
More Novelty      ↔ Less Focus
Longer Outputs    ↔ More Compute
```
